Unlike the transport and application layers, there is a piece of the network layer in each and every host and router in the network. Note that the routers have no upper layers above the network layer because routers do not run application and transport-layer protocols.

---
### Forwarding vs. Routing

| **Feature**        | **Data Plane (Forwarding)**                                          | **Control Plane (Routing)**                                                   |
| ------------------ | -------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **Scope**          | Router-local (navigating a single interchange)                       | Network-wide (planning the entire end-to-end trip)                            |
| **Primary Action** | Moves arriving packets from an input link to the correct output link | Determines the overarching path packets take from sender to receiver          |
| **Timescale**      | Nanoseconds (implemented in hardware)                                | Seconds (implemented in software)                                             |
| **Mechanism**      | Reads packet headers and executes a **Forwarding Table** lookup      | Executes **Routing Algorithms** to compute and populate the Forwarding Tables |

---
### The Control Plane: Two Architectures

The way a router gets its Forwarding Table defines the network's architecture. 

- **The Traditional Approach:** Every single router contains both data-plane hardware and control-plane software. The routing algorithm runs inside the router itself, constantly talking to neighbouring routers via routing protocols (like OSPF or BGP) to collaboratively calculate the Forwarding Table.

![[Screenshot 2026-09-27 at 10.12.26 PM.png]]

- **The SDN Approach (Software-Defined Networking):** The control plane is physically separated from the router. A remote, centralised server (the SDN Controller) computes the end-to-end paths for the entire network and pushes the resulting Forwarding Tables down to the routers. The routers exist solely to execute data-plane forwarding.

![[Screenshot 2026-09-27 at 10.12.08 PM.png]]

An unrealistic, but technically feasible solution is maintenance by human network operators physically present at the routers. In this case, no routing protocols would be required. Operators would need to communicate to ensure that the forwarding tables were configured correctly. It’s likely that this would be more error-prone and much slower to respond to changes in the network topology than a routing protocol.

### The Internet Service Model

A network's service model dictates what guarantees it makes to the transport layer (TCP/UDP) regarding packet delivery. While other architectures (like ATM network architecture) guarantee in-order delivery, bounded delay, and guaranteed minimal bandwidth, the Internet makes **zero guarantees**. Packets might be lost, delivered out of order, indefinitely delayed, or throttled. Internet just provides a **Best-Effort Service**. A network that delivered no packets to the destination would satisfy the definition of best-effort delivery service

There have also been proposed service model extensions to the Internet architecture, for example, the **Intserv architecture** which aims to provide end-end delay guarantees and congestion-free communication. Interestingly, in spite of these well-developed alternatives, the Internet’s basic best-effort service model combined with adequate bandwidth provisioning and bandwidth-adaptive application-level protocols such as the DASH protocol we encountered in Section 2.6.2 have been good enough to enable an amazing range of applications

### Terminology 

 - The terms forwarding and switching are used interchangeably

- We’ll reserve the term packet switch to mean a general packet-switching device that transfers a packet from input link interface to output link interface, according to values in a packet’s header fields.  Both are packet switches, but they operate at different layers:

	1. **Link-Layer Switch (Layer 2):** Forwards packets based on values in the fields of the link-layer frame (covered in Chapter 6).
	2. **Router (Layer 3):** Forwards packets based on on header field values in the network-layer datagram.

### Components of a Router

![[Screenshot 2026-09-27 at 10.11.49 PM.png]]

It consists of four main physical components:

1. **Input Ports:**

	- These refer to physical hardware router interfaces, which are completely distinct from software application ports.  In practice, the number of ports supported by a router can range from a relatively small number in enterprise routers, to hundreds of 10 Gbps ports in a router at an ISP’s edge, where the number of incoming lines tends to be the greatest. 
	
	- They perform the physical-layer function of terminating the incoming link, shown as the leftmost box of the input port in the image above.
	
	- They execute link-layer functions necessary to interoperate with the other side of the incoming link, represented by the middle box.
	
	- They perform a lookup function (the rightmost box of the input port) by consulting the forwarding table to determine which output port the packet should be sent to via the switching fabric.
	
	- They also identify and forward control packets (such as routing protocol information) up to the routing processor.

2. **Switching Fabric:**
    
    - The switching fabric connects the router’s input ports to its output ports. This switching fabric is completely contained within the router, a network inside of a network router.

3. **Output Ports:**

	- They store packets that have been received from the internal switching fabric.
	
	- They execute the required link-layer and physical-layer operations (shown in the middle and rightmost box of the output port) to transmit these packets onto the outgoing wire.
	
	- If the connection is bidirectional, the output port is typically physically paired with a corresponding input port on the same line card. A line card houses multiple ports where each port has an input and an output chip. A single cable containing both "send" and "receive" wires can connect to these ports. Incoming data goes into the switching fabric and goes to the output chip of a specific port  (which may be on a separate line card). Modular chassis routers allow adding multiple line cards for scalability.

    - Runs the control-plane software. In traditional routers it calculates the Forwarding Table (via routing protocols) or as in SDN Routers, it receives it from a remote controller, then installs these entries in the router's input ports.
    
    - The routing processor also performs the network management (covered in Section 5.7).

### Hardware vs. Software.

- **Data Plane is implemented in Hardware (Nanoseconds):** If an input port is receiving a 100 Gbps stream of 64-byte IP datagrams, it has exactly 5.12 nanoseconds to process each packet. If N ports are combined on a line card (as is often done in practice), the datagram-processing pipeline must operate N times faster, far too fast for software implementation. Forwarding hardware can be implemented either using a router vendor’s own hardware designs, or constructed using purchased merchant-silicon chips (for example, as sold by companies such as Intel and Broadcom). 

- **Control Plane is implemented in Software (Milliseconds/Seconds):** Calculating network paths is complex but doesn't happen per-packet. The Routing Processor runs standard  software on a normal CPU to handle a router’s control functions, executing the routing protocols, communicating with the remote controller (in the SDN case) and performing management functions.

### Forwarding Types

When the Input Port does its lookup, it uses one of two paradigms:

- **Destination-Based Forwarding:** The router determines the output port by looking exclusively at the packet's final Destination IP Address.

- **Generalized Forwarding:** The router determines the output port, or executes other actions, based on a combination of multiple packet header fields (e.g., Source IP, TCP/UDP ports, Protocol). This allows the network device to route traffic differently based on its origin, prioritise specific packets, or block them entirely (acting as a firewall).
