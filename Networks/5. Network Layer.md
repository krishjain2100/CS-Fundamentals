Unlike the transport and application layers, there is a piece of the network layer in each and every host and router in the network. Note that the routers have no upper layers above the network layer because routers do not run application and transport-layer protocols.

---
### Forwarding vs. Routing

| **Feature**        | **Data Plane (Forwarding)**                                          | **Control Plane (Routing)**                                                   |
| ------------------ | -------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **Scope**          | Router-local (navigating a single interchange)                       | Network-wide (planning the entire end-to-end trip)                            |
| **Primary Action** | Moves arriving packets from an input link to the correct output link | Determines the overarching path packets take from sender to receiver          |
| **Timescale**      | Nanoseconds (implemented in hardware)                                | Seconds (implemented in software)                                             |
| **Mechanism**      | Reads packet headers and executes a **Forwarding Table** lookup      | Executes **Routing Algorithms** to compute and populate the Forwarding Tables |

---
### The Control Plane: Two Architectures

The way a router gets its Forwarding Table defines the network's architecture. 

- **The Traditional Approach:** Every single router contains both data-plane hardware and control-plane software. The routing algorithm runs inside the router itself, constantly talking to neighbouring routers via routing protocols (like OSPF or BGP) to collaboratively calculate the Forwarding Table.

![[Screenshot 2026-09-27 at 10.12.26 PM.png]]

- **The SDN Approach (Software-Defined Networking):** The control plane is physically separated from the router. A remote, centralised server (the SDN Controller) computes the end-to-end paths for the entire network and pushes the resulting Forwarding Tables down to the routers. The routers exist solely to execute data-plane forwarding.

![[Screenshot 2026-09-27 at 10.12.08 PM.png]]

An unrealistic, but technically feasible solution is maintenance by human network operators physically present at the routers. In this case, no routing protocols would be required. Operators would need to communicate to ensure that the forwarding tables were configured correctly. It’s likely that this would be more error-prone and much slower to respond to changes in the network topology than a routing protocol. 

---
### The Internet Service Model

A network's service model dictates what guarantees it makes to the transport layer (TCP/UDP) regarding packet delivery. While other architectures (like ATM network architecture) guarantee in-order delivery, bounded delay, and guaranteed minimal bandwidth, the Internet makes **zero guarantees**. Packets might be lost, delivered out of order, indefinitely delayed, or throttled. Internet just provides a **Best-Effort Service**. A network that delivered no packets to the destination would satisfy the definition of best-effort delivery service

There have also been proposed service model extensions to the Internet architecture, for example, the **Intserv architecture** which aims to provide end-end delay guarantees and congestion-free communication. Interestingly, in spite of these well-developed alternatives, the Internet’s basic best-effort service model combined with adequate bandwidth provisioning and bandwidth-adaptive application-level protocols such as the DASH protocol we encountered in Section 2.6.2 have been good enough to enable an amazing range of applications

### Terminology 

 - The terms forwarding and switching are used interchangeably

- We’ll reserve the term packet switch to mean a general packet-switching device that transfers a packet from input link interface to output link interface, according to values in a packet’s header fields.  Both are packet switches, but they operate at different layers:

	1. **Link-Layer Switch (Layer 2):** Forwards packets based on values in the fields of the link-layer frame (covered in Chapter 6).
	2. **Router (Layer 3):** Forwards packets based on on header field values in the network-layer datagram.

### Components of a Router

![[Screenshot 2026-09-27 at 10.11.49 PM.png]]

It consists of four main physical components:

1. **Input Ports:**

	- These refer to physical hardware router interfaces, which are completely distinct from software application ports.  In practice, the number of ports supported by a router can range from a relatively small number in enterprise routers, to hundreds of 10 Gbps ports in a router at an ISP’s edge, where the number of incoming lines tends to be the greatest. 
	
	- They perform the physical-layer function of terminating the incoming link, shown as the leftmost box of the input port in the image above.
	
	- They execute link-layer functions necessary to interoperate with the other side of the incoming link, represented by the middle box.
	
	- They perform a lookup function (the rightmost box of the input port) by consulting the forwarding table to determine which output port the packet should be sent to via the switching fabric.
	
	- They also identify and forward control packets (such as routing protocol information) up to the routing processor.

2. **Switching Fabric:**
    
    - The switching fabric connects the router’s input ports to its output ports. This switching fabric is completely contained within the router, a network inside of a network router.

3. **Output Ports:**

	- They store packets that have been received from the internal switching fabric.
	
	- They execute the required link-layer and physical-layer operations (shown in the middle and rightmost box of the output port) to transmit these packets onto the outgoing wire.
	
	- If the connection is bidirectional, the output port is typically physically paired with a corresponding input port on the same line card. A line card houses multiple ports where each port has an input and an output chip. A single cable containing both "send" and "receive" wires can connect to these ports. Incoming data goes into the switching fabric and goes to the output chip of a specific port  (which may be on a separate line card). Modular chassis routers allow adding multiple line cards for scalability.

4. **Routing Processor:**
    
    - Runs the control-plane software. In traditional routers it calculates the Forwarding Table (via routing protocols) or as in SDN Routers, it receives it from a remote controller, then installs these entries in the router's input ports.
    
    - The routing processor also performs the network management (covered in Section 5.7).

---
### Hardware vs. Software.

- **Data Plane is implemented in Hardware (Nanoseconds):** If an input port is receiving a 100 Gbps stream of 64-byte IP datagrams, it has exactly 5.12 nanoseconds to process each packet. If N ports are combined on a line card (as is often done in practice), the datagram-processing pipeline must operate N times faster, far too fast for software implementation. Forwarding hardware can be implemented either using a router vendor’s own hardware designs, or constructed using purchased merchant-silicon chips (for example, as sold by companies such as Intel and Broadcom). 

- **Control Plane is implemented in Software (Milliseconds/Seconds):** Calculating network paths is complex but doesn't happen per-packet. The Routing Processor runs standard  software on a normal CPU to handle a router’s control functions, executing the routing protocols, communicating with the remote controller (in the SDN case) and performing management functions.

---
### Forwarding Types

When the Input Port does its lookup, it uses one of two paradigms:

- **Destination-Based Forwarding:** The router determines the output port by looking exclusively at the packet's final Destination IP Address.

- **Generalized Forwarding:** The router determines the output port, or executes other actions, based on a combination of multiple packet header fields (e.g., Source IP, TCP/UDP ports, Protocol). This allows the network device to route traffic differently based on its origin, prioritise specific packets, or block them entirely (acting as a firewall).

---
### Input Port Processing

- **Network Layer:** Consults the forwarding table to determine the correct output port and pushes the packet into the switching fabric. If the switching fabric is currently in use, the packet is temporarily queued at the input port.

- **Auxiliary Actions:**
    - Checks the packet's version number, checksum, and Time-To-Live (TTL) fields.
    - Rewrites the checksum and TTL fields.
    - Updates network management counters (e.g., number of IP datagrams received).

![[Screenshot 2026-09-27 at 11.35.26 PM.png]]

---
### Forwarding Table Architecture

- **Decentralised Execution:** The centralized routing processor (or remote SDN controller) calculates the forwarding table and pushes a shadow copy to each input line card over a separate internal bus (e.g., a PCI bus). Each line card gets the same single copy and each input chip on the line card uses this single copy.

- **Bottleneck Avoidance:** Maintaining copies allows input ports to make local forwarding decisions simultaneously without invoking the routing processor on a per-packet basis.

---
### Destination-Based Forwarding Mechanics

- **Prefix Matching:** Because 32-bit IP addresses yield over 4 billion possible combinations, brute-force exact-match tables are impossible. Routers instead group address ranges into prefixes. The router matches the prefix of an incoming packet's destination address against the table entries.

- **Longest Prefix Matching Rule:** If a single destination address matches multiple prefix entries in the table, the router forwards the packet to the link interface associated with the longest matching prefix. We’ll see why this rule is useful in Section 4.3.

- **Hardware Acceleration:** At Gigabit transmission rates, lookups must execute in nanoseconds. This requires hardware implementation using embedded on-chip DRAM and fast SRAM (acting as a DRAM cache).

- **Ternary Content Addressable Memories (TCAMs):** Specialized hardware that retrieves the correct forwarding table entry in constant time. Enterprise routers can hold upwards of one million TCAM entries.

- Once a packet’s output port has been determined via the lookup, the packet can be sent into the switching fabric.

---
### Match Plus Action Abstraction

Lookup and forwarding is a specific implementation of a universal network device paradigm: Matching a packet header field and executing a specific action.

| **Device**                                               | **Match Criteria**             | **Action Executed**                          |
| -------------------------------------------------------- | ------------------------------ | -------------------------------------------- |
| **Router (Layer 3)**                                     | Destination IP Address         | Forwards packet to the specified output port |
| **Link-Layer Switch (Layer 2)**                          | Destination MAC Address        | Forwards frame toward the output port        |
| **Firewall**                                             | IP Addresses & Transport Ports | Drops or blocks the packet                   |
| **NAT (Network Address Translator)** <br>(To be covered) | Transport-layer Port Number    | Rewrites the port number                     |

### Switching Fabrics

The switching fabric forwards packets from an input port to an output port.

**Switching via Memory**

- **Legacy Architecture:** Operated under direct CPU (routing processor) control. An input port triggered an interrupt, copied the packet into processor memory, and the CPU extracted the destination, performed the lookup, and copied the packet to the output buffer.

- **Bandwidth Constraint:** If memory bandwidth allows a maximum of B packets per second to be written/read, total forwarding throughput is strictly limited to less than B/2. Shared system buses prevent simultaneous packet forwarding.

- **Modern Execution:** Input line cards independently perform lookups and write packets directly into the appropiate output port's portion of a large global shared memory, resembling shared-memory multiprocessors (e.g., Cisco Catalyst 8500).


**Switching via a Bus**

- **Mechanism:** The input port prepends a switch-internal label indicating the target output port and broadcasts the packet across a shared bus, entirely bypassing the routing processor. All output ports receive the broadcast, but only the matching port captures the packet and strips the temporary label.

- **Bandwidth Constraint:** Strictly sequential. Switching speed is completely bottlenecked by the single bus speed. Simultaneous packet arrivals at different input ports force all but one packet to wait in queue.

- **Use Case:** Sufficient for small local area and enterprise networks (e.g., Cisco 6500 operating over a 32-Gbps backplane bus).


**Switching via an Interconnection Network**

- **Crossbar Switch Mechanism:** A grid of 2N buses connecting N input ports to N output ports. A dedicated switch fabric controller (whose logic is part of the switching fabric itself) dynamically opens and closes intersections (crosspoints) between vertical and horizontal buses. The intersection between A and Y is closed when input is from port A and output is to port Y.

- **Parallelism (Non-Blocking):** Capable of forwarding multiple packets simultaneously, provided they target _different_ output ports. If multiple packets target the exact same output port, only one transmits while the others queue at the input port.


![[Screenshot 2026-09-28 at 12.09.23 AM.png]]

**Advanced Interconnection Scaling**

- **Multi-Stage Switching:** Employs multiple stages of switching elements to allow packets from different input ports to proceed toward the exact same output port simultaneously.

![[Screenshot 2026-09-28 at 1.56.47 AM.png]]

For same output case, there can be a queue at the output port if it cannot take multiple packets simultaneously.

- **Parallel Fabrics (Chunk Spraying):** Routers scale capacity by running $N$ switching fabrics in parallel. The input port fragments a packet into $K$ smaller chunks, transmits them simultaneously across $K$ fabrics, and the output port reassembles the original packet.

### Output Port Processing

![[Screenshot 2026-09-28 at 12.10.02 AM.png]]

- **Core Function:** Takes packets stored in the output port’s memory and drives them onto the physical outgoing wire.

- **Execution:** Handles packet scheduling (selecting which queued packet to send next), de-queueing, and all required link-layer and physical-layer transmission functions.

### Queuing Dynamics in Routers

- **Determinants:** The location and severity of queuing depend entirely on traffic load, line transmission speed ($R_{line}$), and the switching fabric transfer rate ($R_{switch}$).

- **Packet Loss:** Occurs strictly when queues grow large enough to exhaust a port's available memory.

---
#### Input Queuing

Occurs when $R_{switch}$ is not suffiicient to handle $R_{line}$. Consider a crossbar switching fabric and suppose that:
- All link speeds are identical
- One packet can be transferred from any one input port to a given output port in the same amount of time it takes for a packet to be received on an input link.
- Packets are moved from an input queue to their desired output queue in an FCFS manner. 
- Multiple packets can be transferred in parallel, as long as their output ports are different.
- However, if two packets at the front of two input queues are destined for the same output queue, then one of the packets will be blocked and must wait at the input queue a the switching fabric can transfer only one packet to a given output port at a time.

**Head-of-the-Line (HOL) Blocking:** A queued packet must wait for transfer (even if its target output port is completely free) because it is trapped behind another packet at the front of the queue that is blocked by output port contention. Due to HOL blocking, input queues grow to unbounded lengths (causing massive packet loss).

![[Screenshot 2026-09-28 at 2.11.08 AM.png]]

Light shaded packet at Input 3 must wait if Dark shaded packet at Input 1 is selected first.

----
#### Solutions to HOL

**Virtual Output Queuing (VOQ)**

- Replaces the single FIFO queue at each input port with $N$ separate logical queues (one dedicated to each of the $N$ output ports).
- If a packet destined for Output X is physically blocked by contention, the scheduler simply bypasses it and transmits a packet from a different VOQ at that same input port destined for a currently available output port.
- Completely eliminates Head-of-the-Line blocking.

**Switch Fabric Speedup**

- Increases the internal switching fabric speed to be $N$ times faster than the input line speed ($R_{switch} = N \cdot R_{line}$).
- Clears all packets immediately upon arrival, physically preventing input queues from forming.
- Shifts the buffering burden and queuing delay entirely to the output ports.

**Combined Input-Output Queuing (CIOQ) with Centralised Scheduling**

- A moderate fabric speedup (e.g., 2x) combined with VOQs to balance hardware costs.
- Requires a centralised bipartite matching algorithm (such as the **iSLIP** algorithm detailed in McKeown's 1997 paper) to iteratively pair non-conflicting input and output ports to maximize throughput during each clock cycle.

---
#### Output Queuing

- **Trigger:** Occurs even if $R_{switch}$ is $N$ times faster than $R_{line}$. If $N$ input ports simultaneously forward packets to the exact same output port, the output port can only transmit one packet per time unit onto the link, forcing the remaining $N-1$ packets to queue.

- **Buffer Exhaustion Policies:**
    - **Drop-Tail:** Immediately drops the newly arriving packet.
    - **Eviction:** Removes one or more already-queued packets to accommodate the new arrival. In some cases, it may be advantageous to drop (or mark the header of) a packet before the buffer is full in order to provide a congestion signal to the sender. This marking could be done using the Explicit Congestion Notification bits discussed earlier.

- **Active Queue Management (AQM):** Algorithms that proactively drop or mark packets (e.g., using Explicit Congestion Notification bits) _before_ the buffer fills to signal incipient congestion to the TCP sender. Examples: **Random Early Detection (RED), PIE (Proportional Integral controller Enhanced), and CoDel.**

- **Scheduling:** Requires a packet scheduler at the output port to select which queued packet is transmitted next.

### Buffer Sizing Architecture

The $RTT$ in the following formulae is the average Round-Trip Time of all the active TCP flows passing through that specific link. A larger $RTT$ means the TCP sender has a much slower reaction time. The router needs a proportionally larger buffer to absorb all the data the sender blindly fires into the network before it finally receives an ACK and adjusts its speed.

| **Environment**                          | **Calculation Formula**             | **Context**                                                                                               |
| ---------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Legacy / Edge (Small TCP Flow Count)** | $B = RTT \times C$                  | Total buffer size ($B$) equals the average Round-Trip Time ($RTT$) multiplied by the link capacity ($C$). |
| **Modern Core (Large TCP Flow Count)**   | $B = \frac{RTT \times C}{\sqrt{N}}$ | Used when a large number of independent TCP flows ($N$) share a backbone link.                            |

**Reasons for Modern Core Router Formula:**

- As the number of independent TCP flows ($N$) scales to the thousands, synchronized bursting becomes statistically impossible. The transmission peaks of some flows perfectly fill the valleys of others, smoothing the aggregate traffic rate.
- Because bandwidth is heavily divided, no individual flow's peak variance is large enough to overwhelm the link capacity.
- Extreme traffic spikes are eliminated, allowing the required physical memory to shrink proportionally by a factor of $\frac{1}{\sqrt{N}}$.

---
### Over-Buffering

While large buffers successfully absorb short-term statistical fluctuations (lowering packet loss), excessive buffer sizing introduces two failure modes:

1. **End-to-End Delay:** A massive buffer means a longer physical queue. Packets spend tens to hundreds of milliseconds trapped in memory waiting for transmission, destroying real-time interactive applications (gaming, VoIP, teleconferencing).

2. **Transport-Level Failure:** TCP relies on Round-Trip Time ($RTT$) as its primary feedback mechanism. Because large buffers trap packets instead of dropping them, the $RTT$ artificially inflates. This lag blinds the TCP sender, making its congestion-control algorithms slow to react to actual network congestion.

---
### Edge Buffer-bloat

The network edge (e.g., home routers) lacks the statistical multiplexing benefits of the core. A single bursty flow can permanently degrade latency. Consider:

A home router link takes 20 ms to transmit a packet. The network RTT is 200 ms. At $t=0$, an initial burst of 25 TCP packets arrives in the queue. In the 200 ms it takes for the first ACK to return, the router processes exactly 10 packets ($200\text{ ms} / 20\text{ ms/packet}$).

**At $t=200$ ms:** The first ACK arrives. The router has transmitted 10 packets and is beginning the 11th. Exactly **15 packets** remain trapped in hardware queue. TCP is ACK-clocked, it sends one new packet every time it receives an ACK. Because the router transmits one packet every 20 ms, an ACK returns to the sender every 20 ms. The sender pushes a new packet into the queue at the exact same rate the router pulls one out.

As a result, the queue locks into an equilibrium, maintaining a permanent, standing length of 15 packets. The pipe operates at maximum throughput, but every subsequent packet suffers a mandatory, permanent queuing delay of 300 ms ($15 \text{ packets} \times 20 \text{ ms}$), destroying real-time application performance.

**Solution:** Because this persistent delay occurs even with zero competing traffic, modern edge standards (like DOCSIS 3.1) mandate **Active Queue Management (AQM)**. AQM intentionally drops packets proactively, signalling TCP to throttle its sending rate and breaking the standing queue without sacrificing bulk throughput.

### Packet Scheduling Disciplines

The packet scheduler determines the exact order in which queued packets are transmitted over an outgoing link.

|**Scheduling Type**|**Mechanism**|**Characteristics & Execution**|
|---|---|---|
|**FIFO (First-In-First-Out)**|Transmits packets strictly in the order they arrived at the output queue.|If the buffer fills, a packet-discard policy dictates drops. Packets are removed from the queue only upon complete transmission.|
|**Priority Queuing**|Classifies incoming packets into strict priority tiers (e.g., routing management over user data), assigning each class its own queue.|The scheduler always transmits from the highest-priority non-empty queue. Ties within a class are resolved via FIFO. Operates **non-preemptively**: an active transmission is never interrupted by a newly arrived higher-priority packet.|
|**Round Robin**|Sorts packets into classes and alternates service equally among them (e.g., Class 1 $\rightarrow$ Class 2 $\rightarrow$ Class 1).|**Work-conserving**: The link never sits idle if packets are queued. If a scheduled class is empty, the scheduler immediately skips to the next class in the sequence.|
|**Weighted Fair Queuing (WFQ)**|A generalized, circular round-robin scheduler where each class $i$ is assigned a specific weight $w_i$.|**Work-conserving** and bandwidth-guaranteeing. Class $i$ receives a guaranteed service fraction of $\frac{w_i}{\sum w_j}$, where the denominator sums the weights of _only_ the currently active (non-empty) classes. Minimum guaranteed throughput is $R \cdot \frac{w_i}{\sum w_j}$ on a link with transmission rate $R$.|

### Net Neutrality & Traffic Classification

Packet scheduling mechanisms (Priority Queuing, WFQ) provide the technical capability for ISPs to enforce differential service levels by classifying traffic based on IP datagram headers (e.g., port numbers or source IP addresses).

**Net Neutrality Principles**

Legislation governing how ISPs can legally utilize these scheduling capabilities (such as the 2015 US FCC Order, later rolled back in 2017) generally focuses on three primary prohibitions:

- **No Blocking:** ISPs cannot block access to lawful content, applications, services, or non-harmful devices.

- **No Throttling:** ISPs cannot intentionally impair or degrade lawful internet traffic based on its content, application, or service type.

- **No Paid Prioritization:** ISPs cannot use traffic shaping, priority queues, or resource reservation to favor specific traffic in exchange for direct or indirect compensation.
